### Цель и задание

Создать две программы на C: родительскую и дочернюю. Родитель получает имя выходного файла и строки с целыми числами. Ребёнок вычисляет сумму чисел в каждой строке и пишет результаты в созданный им файл. Для обмена используются два неименованных канала.

### Архитектура решения

```text
пользователь → parent → pipe1 → child → файл результатов
                 parent ← pipe2 ← child
```

Родитель создаёт `pipe1` и `pipe2`, затем вызывает `fork`. В дочерней ветке `dup2` подключает `pipe1` к стандартному вводу, а `pipe2` — к стандартному выводу. `execl` запускает отдельную программу `child`, передавая ей имя файла. После открытия файла ребёнок отправляет ответ `R`. Для каждой строки он отправляет `O`, если сумма записана, или `E`, если строка некорректна. Родитель ждёт ответ, прежде чем отправить следующую строку. При завершении ввода родитель закрывает канал и вызывает `waitpid`.

`../src/parent.c` управляет процессом и каналами, `../src/child.c` обрабатывает строки и файл, `../src/sum.c` разбирает числа и проверяет переполнение, `../src/common.c` содержит общие функции записи, закрытия дескрипторов и обработки `SIGPIPE`.

### Ключевой фрагмент

В дочерней ветке родительской программы каналы подключаются к стандартным потокам, затем запускается `child`:

```c
if (dup2(to_child[0], STDIN_FILENO) == -1 ||
    dup2(from_child[1], STDOUT_FILENO) == -1) {
    perror("dup2");
    _exit(127);
}

execl("./build/child", "child", filename, (char *)NULL);
perror("execl");
_exit(127);
```

Между `dup2` и `execl` программа закрывает лишние концы обоих каналов. `write_all` обрабатывает частичную запись; строки произвольной длины читаются через `getline`. По окончании родитель закрывает дескрипторы и дожидается ребёнка, поэтому зомби-процесс не остаётся.

### Сборка и результаты

Из каталога `lab_2`:

```sh
make
./build/parent
```

22 ноября 2026 года программа собрана и проверена в Linux-контейнере Debian 13 (aarch64), GCC 14.4.0. Пример ввода: имя `/tmp/results.txt`, затем строки `1 2 3`, `-5 10`, `abc`, `2147483647 1`, `4`. В файл записаны суммы:

```text
6
5
4
```

Некорректная строка и переполнение суммы были отклонены; обработка следующих строк продолжилась. В консоли показаны PID родителя и ребёнка. При отдельном запуске под `strace -ff` наблюдались следующие вызовы (длинные аргументы сокращены):

```text
pipe2([3, 4], 0) = 0
pipe2([5, 6], 0) = 0
clone(...SIGCHLD...) = 86
dup3(3, 0, 0) = 0
dup3(6, 1, 0) = 1
execve("./build/child", ["child", "/tmp/out.txt"], ...) = 0
wait4(86, [{WIFEXITED(s) && WEXITSTATUS(s) == 0}], 0, NULL) = 86
```

Вызовы `pipe2` создают каналы; `clone` создаёт дочерний процесс; `dup3` перенаправляет его ввод и вывод; `execve` заменяет программу ребёнка; `wait4` позволяет родителю дождаться завершения.
