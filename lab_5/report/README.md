## 1. Цель и задание

Цель работы — создать динамические библиотеки с общим контрактом и использовать их двумя способами: подключить библиотеку при компоновке программы и загрузить её во время исполнения через интерфейс ОС.

Для варианта 1 нужны две функции:

```c
float SinIntegral(float A, float B, float e);
float Derivative(float A, float delta_x);
```

Первая функция вычисляет интеграл `sin(x)` на отрезке `[A, B]` с шагом `e`: реализация 1 использует метод прямоугольников, реализация 2 — метод трапеций. Вторая вычисляет производную `cos(x)` в точке `A`: реализация 1 использует разность `(cos(A + deltaX) - cos(A)) / deltaX`, реализация 2 — `(cos(A + deltaX) - cos(A - deltaX)) / (2 * deltaX)`.

Требуется подготовить две библиотеки и две программы. Программа 1 использует реализацию 1, выбранную при компоновке. Программа 2 загружает библиотеку по относительному пути во время работы и переключает реализацию по команде `0`. Команды `1` и `2` вызывают соответствующие функции и выводят результат.

## 2. Организация программы

```text
program1 ── компоновка ──> libimpl1.so

program2 ── dlopen / dlsym ──> libimpl1.so
         └─ команда 0 ────> libimpl2.so
```

Контракт объявлен в `include/contract.h`. Обе библиотеки экспортируют функции с одинаковыми именами и сигнатурами. Общий разбор команд находится в `src/cli.c`, поэтому обе программы одинаково проверяют ввод и печатают результаты.

`program1` вызывает функции напрямую. Компоновщик записывает зависимость от `libimpl1.so` в исполняемый файл; загрузчик Linux открывает эту библиотеку при запуске программы. В сборке используется `RUNPATH=$ORIGIN`, чтобы загрузчик искал библиотеку рядом с исполняемым файлом.

`program2` при запуске вызывает `dlopen("./build/libimpl1.so", RTLD_NOW | RTLD_LOCAL)`, получает адреса `SinIntegral` и `Derivative` через `dlsym` и сохраняет их в указателях на функции. Команда `0` загружает другую библиотеку, проверяет наличие обеих функций, затем закрывает прежнюю библиотеку через `dlclose`. Если новая библиотека недоступна, прежняя остаётся активной. Относительные пути требуют запуска из каталога `lab_5`.

Для интегрирования отрезок разбивается на шаги длиной не более `e`; последний шаг при необходимости короче. В первом методе площадь участка равна `sin(x) · Δx`, во втором — `(sin(x) + sin(x + Δx)) · Δx / 2`. Если `A > B`, результат меняет знак. Внутренние вычисления выполняются в `double`, результат приводится к `float` согласно контракту.

## 3. Ключевые фрагменты реализации

Фрагмент реализации интеграла методом трапеций:

```c
for (double x = left; x < right;) {
    double next = fmin(x + (double)e, right);
    if (next <= x) {
        errno = ERANGE;
        return NAN;
    }
    sum += (sin(x) + sin(next)) * (next - x) / 2.0;
    x = next;
}
```

Получение функций из динамической библиотеки в программе 2:

```c
void *handle = dlopen(path, RTLD_NOW | RTLD_LOCAL);
sin_integral_fn integral = (sin_integral_fn)dlsym(handle, "SinIntegral");
derivative_fn derivative = (derivative_fn)dlsym(handle, "Derivative");
```

Полный код расположен в `src/impl1.c`, `src/impl2.c`, `src/program1.c`, `src/program2.c` и `src/cli.c`. После `dlsym` проверяется `dlerror`; указатели начинают использоваться только после успешной загрузки обеих функций.

## 4. Сборка и проверка

Проверка выполнена 23 ноября 2026 года в Linux-контейнере на архитектуре aarch64 с GCC 14.4.0 и glibc 2.41. Сборка:

```sh
cd lab_5
make clean all
```

Для сравнения методов использованы команды `1 0 3.1415927 0.001` и `2 1 0.001`. Точное значение первого выражения близко к `2`, производная второго равна `-sin(1) ≈ -0.841470985`.

| Команда | Реализация 1 | Реализация 2 |
|---|---:|---:|
| `1 0 3.1415927 0.001` | `1.99999976` | `1.99999988` |
| `2 1 0.001` | `-0.841741025` | `-0.841470838` |

Пример переключения в программе 2:

```text
$ printf '1 0 1 0.25\n0\n1 0 1 0.25\n0\n1 0 1 0.25\n' | ./build/program2
0.352117062
Реализация 2
0.457300931
Реализация 1
0.352117062
```

Реализации дают разные приближения на крупном шаге `0.25`, а повторное переключение возвращает первый результат. Проверены также обратный порядок границ (`1 1 0 0.25` даёт `-0.352117062` в реализации 1), нулевой шаг, нулевое приращение, неверное число аргументов и текст вместо числа. При ошибке ввода программа сообщает о ней и продолжает принимать команды. При удалённой второй библиотеке `program2` сообщает об ошибке `dlopen`, после чего первая библиотека остаётся доступной.

Сведения о зависимостях получены командой `readelf -d`:

```text
program1: NEEDED libimpl1.so; NEEDED libm.so.6; RUNPATH [$ORIGIN]
program2: NEEDED libm.so.6; NEEDED libc.so.6
```

В `program2` нет записанной зависимости от `libimpl1.so` или `libimpl2.so`: имена библиотек передаются `dlopen` во время выполнения. Отсутствие отдельной записи `libdl.so` связано с тем, что в используемой версии glibc функции `dlopen` входят в `libc`.

## 5. Сравнение способов подключения

| Свойство | Программа 1: компоновка | Программа 2: загрузка при работе |
|---|---|---|
| Выбор реализации | Во время сборки | Во время работы, команда `0` |
| Вызов функции | Прямой вызов по контракту | Через указатель, полученный `dlsym` |
| Отсутствие библиотеки | Программа не запускается | Ошибка `dlopen` обрабатывается программой |
| Замена реализации | Требует другой сборки или замены подключаемой библиотеки | Выполняется без перезапуска |

Оба способа используют динамические библиотеки. Разница состоит в том, когда определяется конкретная библиотека и кто управляет её загрузкой: системный загрузчик по записи `NEEDED` или сама программа через `dlopen`.
