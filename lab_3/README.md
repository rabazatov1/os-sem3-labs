# Лабораторная работа №3 — битоническая сортировка, вариант 1

Программа сортирует массив целых чисел с помощью POSIX-потоков в Linux. Ключ `--threads` задаёт максимум одновременно существующих потоков, включая главный.

## Сборка и запуск

```sh
make
printf '7 9 -2 4 4 0 7 -8\n' | ./build/bitonic --threads 3
```

Первое число во входе — длина массива, затем идут его элементы через пробел или перевод строки. Отсортированный массив печатается в `stdout`, PID, TID, число потоков и время сортировки — в `stderr`. Для входа из файла:

```sh
printf '7 9 -2 4 4 0 7 -8\n' > /tmp/input.txt
./build/bitonic --threads 4 < /tmp/input.txt > /tmp/sorted.txt
```

Массив временно дополняется значениями `INT_MAX` до ближайшей степени двойки. На каждой стадии пара `i` и `i ^ j` сравнивается один раз. Главный поток и рабочие потоки обрабатывают разные диапазоны индексов; `pthread_barrier_t` не даёт перейти к следующей стадии, пока все не закончили текущую. При `--threads 4` создаются три рабочих потока. После сортировки все они завершаются через `pthread_join`.

## Проверка числа потоков

В первом терминале запустите программу с паузой перед сортировкой:

```sh
./build/bitonic --threads 4 --pause 10 < /tmp/input.txt
```

В другом терминале подставьте напечатанный PID:

```sh
ps -L -p PID -o pid,tid,comm
ls /proc/PID/task | wc -l
```

Для просмотра создания и ожидания потоков:

```sh
strace -f -e trace=clone,clone3,futex ./build/bitonic --threads 4 < /tmp/input.txt
```

## Измерение времени

Подготовьте один и тот же входной файл и запустите сортировку с разным пределом потоков:

```sh
for p in 1 2 4 8; do
    ./build/bitonic --threads "$p" < /tmp/input.txt > /dev/null
done
```

Измеряемое программой время не включает чтение и печать массива, создание потоков и паузу. Ускорение `S(p) = T(1) / T(p)`, эффективность `E(p) = S(p) / p`. Результаты нескольких размеров и типов входа приведены в [отчёте](report/README.md).
