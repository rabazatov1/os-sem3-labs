### Цель и задание

Освоить файловое отображение для обмена данными между процессами. Родитель принимает имя файла результатов и строки целых чисел. Дочерняя программа вычисляет сумму чисел в каждой корректной строке и записывает её в файл. Как и в ЛР2, родитель и ребёнок представлены разными программами; в ЛР4 строка передаётся через отображаемый файл.

### Архитектура решения

```text
пользователь → parent → mmap(MAP_SHARED) → child → файл результатов
                    SIGUSR1 →       ← SIGUSR2
```

Родитель создаёт временный файл через `mkstemp`, задаёт ему размер через `ftruncate` и сразу удаляет имя через `unlink`. Открытый дескриптор наследуется ребёнком при `fork` и передаётся программе `child` после `execl`. Для каждой строки родитель меняет размер файла по длине строки, отображает его через `mmap`, записывает строку и посылает `SIGUSR1`. Ребёнок после получения сигнала отображает тот же файл, считает сумму, записывает её в файл результатов и посылает `SIGUSR2`. Следующая строка отправляется только после ответа на предыдущую.

В общей области находятся длина строки и состояние запроса. Состояние — атомарная переменная; запись и чтение с порядком release/acquire обеспечивают публикацию данных между процессами. Сигналы используются для пробуждения. `msync` для передачи данных не требуется: оба процесса видят изменения в `MAP_SHARED`; `msync` относится к сохранению изменений на носителе. Родитель ожидает также `SIGCHLD`, чтобы не зависнуть, если ребёнок завершится до ответа. После обмена родитель вызывает `waitpid`. Отображения и дескрипторы закрываются.

### Ключевые фрагменты кода

Родитель задаёт размер отображения по длине введённой строки и публикует запрос:

```c
size_t bytes = sizeof(shared_data) + length + 1;
if (ftruncate(fd, (off_t)bytes) == -1) {
    perror("ftruncate");
    return -1;
}
shared_data *data = mmap(NULL, bytes, PROT_READ | PROT_WRITE,
                         MAP_SHARED, fd, 0);
if (data == MAP_FAILED) {
    perror("mmap");
    return -1;
}
data->length = length;
memcpy(data->line, line, length);
data->line[length] = '\0';
atomic_store_explicit(&data->state, STATE_REQUEST, memory_order_release);
if (munmap(data, bytes) == -1) {
    perror("munmap");
    return -1;
}
if (kill(child, SIGUSR1) == -1) {
    perror("kill(SIGUSR1)");
    return -1;
}
```

В программе ошибки `ftruncate`, `mmap`, `munmap` и `kill` проверяются до перехода к следующему действию. Ребёнок после сигнала читает состояние и строку из своего отображения, затем устанавливает `STATE_OK`, `STATE_INVALID` или `STATE_IO_ERROR` и уведомляет родителя сигналом `SIGUSR2`.

Из каталога `lab_4`:

```sh

cat /tmp/results.txt
```

23 ноября 2026 года в Linux-контейнере Debian 13 (aarch64), GCC 14.4.0 получены суммы:

```text

```

Некорректная строка и переполнение суммы были отклонены, затем обработка продолжилась. Строка из 150 000 чисел `1` дала сумму `150000`. Также проверены строка без завершающего перевода, ошибки открытия и записи файла, ошибка запуска `child` и принудительное завершение ребёнка. В последнем случае родитель получил `SIGCHLD`, вывел ошибку и завершился без зависания.

### Вывод

Два отдельных процесса обмениваются строками и состоянием через отображаемый файл. Сигналы согласуют их работу, а ожидание `SIGCHLD` позволяет обнаружить смерть ребёнка. Корректность подтверждена обычными и отказными сценариями и трассировкой системных вызовов Linux.
